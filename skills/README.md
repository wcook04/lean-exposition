# Authoring transitions

These skills teach decisions that the CLI cannot make. They can be read by a
human or copied into an agent's supported skill directory. The Python package
does not load or execute them.

| Starting point | Task | Skill |
| --- | --- | --- |
| Identified source files | Record claims, assumptions and their support | [Source to graph](source-to-graph/SKILL.md) |
| Selected Lean corpus, original arguments, literature and evidence graph | Reconstruct the complete selected argument | [Graph to long record](graph-to-long/SKILL.md) |
| All those sources plus the long record | Select a contribution and retain its decisive proof | [Long record to short paper](long-to-short/SKILL.md) |
| All those sources plus the long record and short paper | Teach the selected result to a specified reader | [Record to exposition](record-to-expository/SKILL.md) |

Use the [authoring guide](../docs/authoring.md) for the shared evidence and
review contract. These stages may expose a mathematical gap. Record that gap
and return to research; a writing transition cannot fill it by changing the
claim's wording.

Inputs accumulate; the scope of the paper need not. Load the matching skill
before selecting material, then apply its review questions to the actual
document. Record consequential choices and observed failures in the existing
review account. The [maintenance loop](../docs/authoring.md#use-and-improve-the-transition-skills)
explains how a revision can improve these instructions without treating every
local preference as a general rule.
